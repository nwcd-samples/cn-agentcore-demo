Business Pain

传统售后为什么慢且难以治理？

系统割裂

客服需在订单、物流、政策和工单系统间反复切换。

非结构化信息

异常原因只存在于承运商网页，没有可直接调用的 API。

计算容易出错

赔付涉及费率、周期、最低额和上限，不应依赖模型心算。

安全与审计困难

凭证分散、工具权限不清，执行失败后难以追踪调用链。

Solution Value

AgentCore 带来的解决方案

✓
一句话驱动业务闭环

Agent 自主规划，但只通过被允许的企业工具执行动作。

✓
安全管理身份与凭证

用户 JWT、模型 API Key 和 M2M Token 各自受控，不写入页面。

✓
连接 API 与遗留网页

Gateway 接企业服务，Browser 补齐没有 API 的第三方页面。

✓
执行过程可观测、可回退

Trace 串联模型与工具，Runtime 端点支持版本灰度和回滚。

Demo Journey

一条请求如何完成售后闭环

01 · Gateway查订单金额、状态、承诺时间、运单号
02 · Browser读物流页定位西安中转中心分拣故障
03 · Gateway取政策费率、周期、最低额和上限
04 · Sandbox算赔付按分计算，避免浮点和心算错误
05 · Gateway开工单先查重，再执行受控写操作
06 · Memory记偏好新会话仍记得短信通知方式
能力边界：Runtime、Gateway、Identity、Browser、Code Interpreter、Observability 为 AgentCore 中国区原生能力；OIDC IdP 与 MemoryLite 是本项目为中国区能力缺口提供的可替换补位层。
